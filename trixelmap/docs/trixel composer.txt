### 🔗 Dependency Flow & Contracts

### 📐 Shared Creative Contract (The "Brain")
Regardless of the mode, all three files implement the same logic loop:
1.  **Perceive** → Read canvas state + memory context.
2.  **Plan** → Decide next action (Local Heuristic, Ollama, or Empire AI).
3.  **Act** → Place a pixel/color (`CreativeAction`).
4.  **Learn** → Update memory (`AutonomousCreativeMemory` / `ExperienceStore`).

### 🔍 Critical Integration Notes
*   **Method Naming Mismatch:**
    *   `terminal_trixel.py` uses `plan_action()` / `execute_action()`.
    *   `enhanced_trixel_core.py` uses `_autonomous_plan()` / `_execute_action()`.
    *   `empire_bridge.py` calls `composer.plan()` / `composer.act()`.
    *   *Note:* A 5-line adapter is needed to attach the bridge to either composer cleanly.
*   **Memory Systems:**
    *   **GUI:** Uses `AutonomousCreativeMemory` (moving averages, tool mastery).
    *   **Terminal:** Uses `ExperienceStore` (persisted to `.zw/experience_log.jsonl` or LMDB) for replay.
*   **Input Sources:**
    *   `terminal_trixel.py` parses `!zw/art.intent` files to prime Ollama prompts.
    *   `empire_bridge.py` receives `!zw/trixel.guidance_request` from a remote broker.
