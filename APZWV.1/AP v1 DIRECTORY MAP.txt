AP v1 DIRECTORY MAP  
====================

Purpose
-------
This document defines the official file layout for the Anti-Python (AP) Protocol v1.
It replaces the ad-hoc, organic v0 structure with a clean, authoritative directory tree.

This ensures:
    • developers know exactly where new v1 components belong  
    • migration from v0 → v1 is controlled  
    • no file is modified out of order  
    • no ghost or obsolete file survives to cause bugs later

3. MIGRATION ORDER (CRITICAL)
----------------------------------------

STEP 1 — Install v1 Specs (DONE)
    antipython_core_v1_spec.txt
    ap_review_policy_v1.txt
    ap_hypothetical_query_v1.txt

STEP 2 — Create v1 file structure (directories only)
    ap/spec/
    ap/engine/
    ap/ui/
    ap/review/
    ap/sandbox/
    ap/zon/
    ap/ai/

STEP 3 — Migrate ONLY parsing layer
    ap_rule parsing moves into a clean v1 file

STEP 4 — Engine Core (Conflicts + Predicate Eval)
    * Do NOT implement hypothetical, opcode bridge, or UI yet *

STEP 5 — After engine core is stable:
    - ZWAP_OpcodeBridge.gd
    - ZWAP_Hypothetical.gd
    - APReviewQueuePanel.gd

STEP 6 — BalancerBot and Review Pipeline

STEP 7 — Scenario Harness + Headless Runner

STEP 8 — ZON packet + external AI design review

STEP 9 — AP Self-Modification Layer


----------------------------------------
4. LONG-TERM STRUCTURE (FINAL FORM)
----------------------------------------

AP will eventually consist of:

1) **Design Layer**
    - Spec files
    - Schema files
    - AI-facing documentation

2) **Execution Layer**
    - Conflict engine
    - Predicate engine
    - Hypothetical sandbox
    - Snapshot/rollback
    - Opcode bridge (to game world)

3) **Introspection Layer**
    - AP Inspector UI
    - ZON packet generator

4) **Evolution Layer**
    - BalancerBot
    - Review Queue
    - Designer approval panel

5) **Testing Layer**
    - Scenario harness
    - Headless simulation mode
