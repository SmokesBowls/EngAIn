EngAIn Workspace Document Audit & Schema/Contract Map
This document presents a comprehensive architectural audit of the formal contracts, schemas, and ABIs stored within /home/mytruelove/Desktop/burdens_of_a_forgotten_past/EngAIn/docs (excluding the progressive_older_docs directory).

EngAIn is not merely a codebase; it is a survival archive with active, authoritative systems embedded within it. To prevent architectural drift, ensure determinism, and enforce human sovereignty, the workspace relies on an interconnected web of versioned, frozen contracts.

1. Executive Summary: The Constitutional Principles
All audited contracts, runtimes, and adapters converge on three core axioms:

Canon outranks convenience: Under no circumstance should a conversational helper, AI agent, or local client render state bypass formal authority, pipeline promotion, or validation.
Deterministic Singularity: World truth is singular and computed. Perception merely samples it, and experience presents it. Divergences are presentation bugs, not state updates.
Structured Write & Read Separation:
Write Path: User (Tier 3) / Agent (Tier 1) → Intent Proposal → AP Gate Validation → Builder Execution → Runtime Snapshot (SSOT).
Read Path: User Query → AP Scope Validation → Bounded Truth Slice (ABI) → Perception Filter (Packet) → Experience framing (Persona/Modality) → User Presentation.
2. Layer-by-Layer Audit of Schemas & Contracts
2.1 The Constitutional / Dragon Layer (docs/dragon/)
This layer governs the interaction between semantic intention (LLM outputs) and deterministic systems. It serves as the constitutional backbone.

DRAGON_AUTHORITY_DOCTRINE_v1.md (FROZEN)
Core Principle: Separates creative semantic enrichment from deterministic execution. "The LLM may enrich intent, but it may not mutate world state."
Key Invariant: Defines the specific roles and boundaries of the User, Dragon (embodied relay), Dolphin/LLM (semantic normalizer), AP Gate, Capability Registry, and Builders.
schema/INTENT_CONTRACT_SCHEMA_v1.json (FROZEN)
Core Principle: A formal JSON Schema enforcing that LLM proposals adhere to a strict hybrid shape containing binding core fields (intent_type, asset_family, operation, authority, metadata) and non-binding enrichment fields (style, mood, materials, lore_references).
Key Invariant: AP Gate and Capability Registry route exclusively on core fields. Builders can read/adapt enrichment fields but must never crash if they are missing or malformed.
WORLD_TRUTH_CONTRACT_v1.md (FROZEN)
Core Principle: Declares that "Truth is singular, deterministic, and precedes observation."
Key Invariant: EngAInRuntime.snapshot is the Single Source of Truth (SSOT). All mutation is delta-only, atomic, and hashed via protocol_envelope.py. Observer state (renderers, AI, clients) must match runtime; runtime never matches the observer.
QUERY_CONTRACT_v1.md (FROZEN)
Core Principle: Governs the read-path. A query must request a bounded, scope-restricted slice of truth rather than dumping raw snapshots.
Key Invariant: Rejects unbounded queries. Requires a truth_anchor hash matching the current runtime state, blocking query mutations or temporal escape in REPLAY mode.
TRUTH_SLICE_ABI_v1.md (FROZEN)
Core Principle: The universal, immutable, hash-anchored handoff object between the runtime state and all downstream observation layers.
Key Invariant: Elevates slice_builders.py output to a formal contract, ensuring Perception, Vision, and Replay consume identical, tier-filtered data.
PERCEPTION_PACKET_CONTRACT_v1.md (FROZEN)
Core Principle: Defines computational observation ("what can be noticed") based on geometric visibility, audibility, distance bands, occlusion, memory decay, and affordances.
Key Invariant: Perception must never generate narrative framing, mood, or prose. The packet entity count must be ≤ the input Truth Slice entity count.
EXPERIENCE_CONTRACT_v1.md (FROZEN)
Core Principle: The first and only layer allowed to introduce narrative framing, dragon voice/persona, modality routing, and controlled fiction.
Key Invariant: Purely stylistic and presentational; it must never mutate state, alter coordinates, or invent facts.

3. Structural Gaps & Recommendations
During this audit, the following critical structural gaps were identified:

Missing Scorer Dependency in MrLore: Both promotion_eligibility_gate.py and promote_candidate.py depend on tools/authority_score_calculator.py, which is currently archived. A formal transition task is required to safely re-anchor this component.
Transitional Fallbacks in Boot.gd: The Godot client Boot.gd contains legacy environment fallback generators. These should be demoted or refactored into the TrixelEnvironmentPlanner to enforce pure client-as-renderer separation.
Mechanical Batch Approvals: Commands like propose_corrections.py --batch automatically assign approval status. Metadata schemas must explicitly distinguish mechanical_batch from human_explicit approvals to maintain audit integrity.
