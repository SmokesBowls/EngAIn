## 5. The Overrule Event

An **Overrule Event** is the only mechanism by which the Human changes the system.

**An Overrule Event does NOT:**
- Directly mutate canon
- Directly edit runtime state
- Bypass AP validation
- Skip parser re-evaluation
- Mutate any subsystem state directly

**An Overrule Event DOES:**
- Invalidate the current derived state
- Record the Override Event in the authority log
- Trigger a complete re-evaluation sequence across all TIER1 systems
- Require all subsystems to recalculate and reach a new consensus

## 6. The Mandatory Re-Evaluation Sequence

When a Human Overrule Event is issued, ALL TIER1 systems must re-evaluate in the following sequence:

```
1. RECORD  → Override Event logged (timestamp, human intent, scope)
2. REPARSE → Narrative rerun through Mettaext
3. REBUILD → ZON/ZONJ reconstructed from new parse
4. REEVAL  → AP (Authority Permission) re-evaluated
5. RERUN   → Runtime State (EngAInOS) recalculated
6. RESPACE → Spatial State (GodotSim) recalculated
7. REFEEL  → Affect State (Engionality) recalculated
8. REMOVE  → Kinematic State (Mechanimation) recalculated
9. RENDER  → Render State (Trixel) recalculated
10. EMIT   → New Consensus Snapshot emitted
```

**No subsystem may partially accept an override.**  
**Acceptance requires COMPLETE re-evaluation.**

## 7. Consensus Conditions

A new consensus state is valid ONLY when:

- All TIER1 systems have completed re-evaluation.
- All TIER1 systems report `CONSENSUS_REACHED`.
- The new state is deterministic (reproducible from the Overrule Event + existing system state).
- The new state is logged and timestamped.
- No subsystem is left in a partially applied state.

**If consensus cannot be reached:**

```
OVERRIDE_REJECTED
REASON: [system(s)] cannot reconcile
REQUIRES: [specific resolution action]
```

## 8. Pass / Fail Conditions for Overrule Events

**An Overrule Event passes when:**
- The event is recorded with clear timestamp and intent.
- All TIER1 systems complete re-evaluation.
- All TIER1 systems agree on the new state.
- A new consensus snapshot is emitted.
- The system can reproduce the new state from the event log.

**An Overrule Event fails when:**
- Any TIER1 system cannot complete re-evaluation.
- Any two TIER1 systems report conflicting states.
- The event is not recorded.
- The new state is non-deterministic.
- The system enters a partial application state.
