COORDINATE_ABI_v1 Compliance Report

What already complies

tile_address.py — correctly positioned as ViewAddress
The ABI names it explicitly as a ViewAddress generator/consumer (§3.2, §10.5). It takes world_cell + CameraRelative and emits a compact camera-relative string. It performs no world-state writes. Compliant.

engain/world/chunks.py — correct derivation formula
world_to_chunk_local_xz uses wx // cs for chunk key and wx - (chunk_x * cs) for local offset, which is exactly the floor-division rule in §6.2.

world_field_nucleus.py chunk derivation
Uses the same // and - arithmetic. Same formula; compliant.

SemanticRenderer.gd (godotnew) — correctly a consumer
Receives terrain_grid, loads atlas, spawns nodes. Does not write back to any world-state record. Positioned as "Consumer only" per §3.2.

TrixelEnvironmentPlanner.gd — does not claim coordinate authority
Produces grid plans and defers to world_field for actual values. §3.2 says it is "Contract producer, not world truth owner." Compliant with that classification.

placement_emitter.py — deterministic ordering contract
Packets are sorted by chunk → grid key, which satisfies the replay determinism invariant in §12.3.

What is ambiguous

1. engain/world/coordinates.py:CoordinateABI name collides with the v1 envelope but is not it
The dataclass has 4 fields: grid_xy, elevation, tile_address, world_cell_3d. It carries none of the required envelope fields from §5.1: no schema_version, authority_level, authoritative, artifact_kind, source, scene_id, semantic_occupancy, spatial_ownership, or determinism. Consumers of this class cannot validate authority — they get an object called CoordinateABI that is actually a lightweight conversion packet.

2. CoordinateABI.tile_address carries a ViewAddress artifact inside a coordinate record
Per §10.5: tile_address.py emits ViewAddressABI, not CoordinateABI. Storing the tile address string inside CoordinateABI as a required field conflates the two layers. The string d49.l19.f57 is observer-relative (it encodes camera direction); a coordinate record must be observer-independent (§4.1).

3. placement_emitter.py:65 — tile_address is hard-coded to a fixed camera direction
tile_address=f"d{grid_x}.u{elev}.f{grid_y}",
This uses d/u/f (down/up/forward) as implicit canonical camera orientation. The address will be misread as stable if a consumer treats it as a world-space key, which is possible given it's inside CoordinateABI.

4. SemanticRenderer.gd:_terrain_height infers elevation from terrain name
deep_water → -0.4, grass → 0.15, etc. are applied directly to node.position.y. §8.2 says visual height offsets are not CoordinateABI elevation. The renderer is not writing to any coordinate record, so it is technically compliant — but it materializes elevation from atlas type without consuming an authoritative elevation datum, making it undeclared perceptual inference.

5. SemanticRenderer.gd:_handle_tile_click writes terrain state from a screen click
_handle_tile_click → update_tile_from_event mutates terrain_grid[gy][gx] directly inside the renderer. §9.3 says the allowed flow is: screen click → raycast/pick → CoordinateABI lookup → selected_coordinate_id. §11.2 explicitly prohibits renderer mutation of world state. This is the one live violation of the contract.

6. The 2D→3D axis mapping is undeclared
grid_elevation_to_world_cell_3d maps grid_y → world_z (Y-up, grid rows = Z axis). This is consistent, but §6.2 says non-standard derivations must be declared in debug_trace.coordinate_derivation. No declaration exists.

Minimum adapter/validator needed

Only two items require immediate code work — everything else is documentation/annotation only.

A. CoordinateRecord envelope validator (Python, ~30 lines)
A function validate_coordinate_record(obj: dict) -> list[str] that checks for the §5.1 required top-level keys and returns a list of missing/wrong fields. No changes to existing structs. Used to gate anything consuming authority-level records.

REQUIRED_TOP_LEVEL = {
    "schema_version": "trixel_coordinate_abi.v1",
    "authority_level": "coordinate_truth",
    "authoritative": True,
    "artifact_kind": "coordinate_record",
}
REQUIRED_POSITION_KEYS = {"world_x", "world_y", "world_z"}
REQUIRED_CHUNK_KEYS = {"chunk_x", "chunk_y", "chunk_z", "chunk_size", "local_x", "local_y", "local_z"}

B. TileAddress.to_view_address_record() method (in tile_address.py)
A method that serialises TileAddress as a ViewAddressABI-compliant dict with authority_level: "observer_relative" and authoritative: false. This makes the perceptual boundary explicit without touching the compact string encoding. ~15 lines.

C. Fix SemanticRenderer.gd:_handle_tile_click (Godot, ~5 lines)
Replace the direct update_tile_from_event(tile_id, "sand") call with a call to a propose_tile_mutation(tile_id, new_terrain) signal or method that wraps the change in the §11.3 mutation envelope shape and routes it to whatever authority layer (runtime or AP gateway) owns the grid. The renderer must not commit the write itself.

D. Annotation only (no code change required):
- Rename CoordinateABI.tile_address to view_address_hint and document it as non-authoritative in engain/world/coordinates.py.
- Add a debug_trace.coordinate_derivation: "grid_y_to_world_z" note to grid_elevation_to_world_cell_3d.
- Annotate _terrain_height in SemanticRenderer.gd as a perceptual visual approximation, not an authoritative elevation source.
